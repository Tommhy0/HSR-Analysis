# 公开实例验证与功能补齐

2026-10-16。本轮在网上查找原作者的实验记录，录入独立期望值后执行程序；未提交或推送 GitHub。

## 验证结果

公开实例与规则对照共 **18 项通过、0 项失败**。其中 9 项来自作者公布的游戏伤害数字，2 项检查同一个护盾实验的有盾 / 无盾比例，另 7 项是公开计算实例或来源规则检查。没有把 18 项都叫作完整实战录像对拍。

伤害实例取自 [arkkus 的原始伤害计算实验](https://docs.google.com/document/d/e/2PACX-1vQ9M7q5jLz9DKkTRlsGiB8RGYyPQyhShbuTbrVPQ7-Ke4_U787MfWzr2NjY-KrQo5Ota4Lj3JrFyge9/pub)，涉及停云、青雀、杰帕德与三月七，分别检查属性抗性、未击破 / 已击破、普攻增伤与攻击变化。输入按作者当时公布的等级、显示面板、倍率和状态抄录；没有用程序输出生成期望值，也没有修改倍率去拟合。

这 9 个整数伤害的最大绝对差为 **0.61 点**。由于作者公开面板经过取整，采用 **1 点绝对容差**，报告逐项显示原始差值。它们是早期版本的基础公式实验，在当前程序上复算通过，不能证明 4.6 所有角色和敌人机制都正确。

护盾实验来自 [bobrokrot 的公开实测记录](https://srl.keqingmains.com/evidence/combat-mechanics/damage/Shielding)：输入公布的未减伤基线，检查 10% 减伤后有盾 / 无盾均显示同一伤害，以及护盾扣除采用减伤后的数值。记录附有[原视频](https://www.youtube.com/watch?v=PiI0gn1wOIo)，但本次浏览器要求登录才能播放，因此仅标为“公开记录的比例核对”，没有声称看完原视频或还原其未公布的完整配装。

行动值对照使用 [KQM 原作者速度说明](https://hsr.keqingmains.com/misc/speed-guide/)及 [SRL 行动排序规则](https://srl.keqingmains.com/combat-mechanics/turn-order/turn-order-mechanics)。轮次与换波还参考[速度表作者对换波重置的说明](https://www.reddit.com/r/HonkaiStarRail/comments/14yiwiw/)；混沌模式与自定义连续行动模式在界面中明确分开。

可复算输入和来源位于 `simulator/public-validation.mjs`；导出的逐项结果为 `outputs/公开实例对照.json`。运行：

```sh
node _scripts/test_public_validation.mjs --report
```

## 对照检出的修正

- **同速排序**：修复前会按整个配置数组排序；敌人排在数组前时会抢在同速我方之前。现在先处理拉条到零的优先级，再按阵营及本方站位稳定排序；回放预测与执行共用规则。
- **终结技时机**：修复前普通技能后的自动终结技会错过本回合结束到期的增益。现在默认在动作后、回合结束前插入，也可逐人选择“回合结束后插入”，用于比较操作策略。
- **多来源减伤**：战斗引擎原先把独立来源相加，现改为逐来源相乘，并在扣护盾前结算；单次计算核心原有乘法逻辑保留。
- **清场后的追击**：最后一个目标已经阵亡且没有其他目标时，不再白白扣除 Archer 的追击充能。
- **生命套装开场**：默认满血按套装生效后的生命上限初始化；显式指定的初始生命仍保留。初始生命字段留空表示满血。
- **刻律德菈属性换算**：仙舟等常驻攻击光环现在先进入有效攻击，再计算对应攻击转暴伤。

## 补齐的功能

**多波次**：最多十波，每波最多五个敌人。根配置的敌方单位用 `wave: 1, 2, ...` 连续编号。未入场敌人不参与行动、仇恨或选取目标。换波保留我方生命、能量、战技点、护盾、增益、角色资源和龙灵；不重复施放入场秘技。开场终结技清掉第一波，也会正确进入第二波。

默认 `waveMode: "moc"` 在换波时重置角色和龙灵的普通行动距离；`"continuous"` 保留我方剩余进度，是显式自定义规则，不标为已完整复刻虚构叙事。回放会切换当前波敌人、显示波次和换波事件；不会提前展示未来波敌人。页顶新增“两波虚卒 · 连续战斗”入口。

**遗器效果新增十套**：自匿星芒的隐士、太空封印站、泛银河商业公司、筑城者的贝洛伯格、停转的萨尔索图、盗贼公国塔利亚、苍穹战线格拉默、出云显世与高天神国、谧宁拾骨地、渊思寂虑的巨树。数值来自固定 4.6 数据库；隐士护盾来源判定读取固定正式脚本。速度、生命、命中、暴击等阈值在战斗中检查，效果明细能显示实际条件加成。商业公司转换的攻击不会作为其他攻击转换的基数。

隐士套必须持有该装备者提供的有效护盾才给暴伤，其他来源的盾不能替代此条件。盾量加成与圣骑士等效果进入实际护盾生成；支持源盾耗尽后撤销对应条件增益。

**页面验证入口**：“公开实例与规则对照”可一键运行、查看来源值 / 程序值 / 差值 / 容差、打开原始来源及导出 JSON，不修改当前队伍配置。

## 本地检查与剩余边界

`npm test` 包含原有数值断言 479 条、配装与四人检查 63 项、回放 17 项、严格队伍 64 项、公开对照 18 项、新增场景与配装检查 19 项、更新器 8 项。独立四人打包启动自检通过；浏览器已检查公开对照、两波换波快照、隐士套的实际盾量及队友条件暴伤。

四人专武队的**完整实战录像对拍仍未完成**。本次能严格复算的公开数字属于基础公式和局部规则，不能据此宣称该队所有伤害及生存结果已验证。特定 Boss 阶段、其余角色 / 装备、其他属性的标准击破及完整控制系统仍有缺口；严格模式继续拒绝未登记机制。新增多波次也不等于已经实现所有玩法的关卡效果、召唤或评分规则。

新增0T录像核验记录见[0T录像对照与操作轴](0T录像对照与操作轴.md)。目前完整录像通过数仍为0；新增来源候选、操作轴及局部六箭检查不计入上述18项。
