## 这轮实际运行了什么

来源字段保存在 `data/validation/zero-cycle-videos.json`。运行 `npm run validate:videos`，生成 `outputs/0T视频对照报告.json` 与 Markdown 报告。报告分别显示候选、缺口、隔离检查；**不会把候选条目计成通过数**。

根据 Hale雨矢公开的六箭循环，执行了一个明确构造的局部资源检查：原版花火、E1 Archer，9 点战技点，爵位已就绪，Archer 充能绳并保留上次终结技原生 5 点能量。程序得到 **6 次战技、220 能量、剩余 1 点战技点**。这只核对该前提下的循环，不是作者整套配装、不检查视频伤害，也不证明来古士 0T。

当前无法完整复现的原因包括：缇宝/银狼没有可执行角色规则，史瓦罗对应关卡与增益未登记，仲裁来古士阶段/黑潮未实现，11箭涉及的特殊额外行动控制仍未接入。3.5/3.6 录像也必须冻结相应历史数值与角色形态，不能直接套用 4.6 强化花火。缺失输入必须补齐后才运行完整对拍，不通过删掉缺口、改低血量、改倍率或调整暴击种子来造结果。

## 新增可复现操作轴

配置 JSON 支持两层控制。队员的 `policy.turnPlan` 指定本人第几个普通回合使用普攻/战技与目标；根配置 `actionPlan` 在指定角色第几次同类动作完成后，按列表顺序插入终结技。受控制的角色必须 `autoUltimate: false`，避免满能自动插入覆盖录像决策。

```json
{
  "actionPlan": [{
    "after": {"actor":"slot-3","key":"skill","kind":"continuation","occurrence":2},
    "actor":"slot-1", "key":"ultimate"
  }]
}
```

队员策略示例：

```json
{"autoUltimate":false,"turnPlan":[
  {"turn":1,"key":"basic","targetId":"enemy-1"},
  {"turn":2,"key":"skill","targetId":"slot-3"}
]}
```

“回合”按该队员的普通行动计数；“第几次动作”按相应角色、动作名、动作类型严格匹配。`normal` 与 Archer 的 `continuation` 分开计数。奇袭首段不伪造独立插入窗口。命令若资源不足、指定目标提前阵亡或尚未入场，会明确报错，不自动换招换靶。结果的 `plan.unused` 列出没执行的指令；仍有漏项不能判为复现成功。

这套接口尚不支持任意命中中途插入、特殊额外行动内的完整手动菜单和每一箭分别换目标，所以不能声称所有 0T 视频操作已经能表达。

## 判定标准

完整对拍须同时满足：版本/角色形态、四人站位与全部配装、敌方波次和关卡效果一致；实际技能顺序、目标、能量、战技点、拉条和关键伤害逐项相符；最后真实清场。混沌按每波轮次判定 0T，不用视频播放时长，也不用把仿真截到 150 AV 当作成功。比较器保留独立原始期望值、容差和首次不符项；没有观察值就保持未完成。

新增 12 项操作轴与对照器自动测试是程序测试，不是 12 条实战录像通过。原有公开对照状态保留，GitHub 不提交。
