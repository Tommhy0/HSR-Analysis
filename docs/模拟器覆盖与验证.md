# 模拟器覆盖与验证

本项目的模拟器使用独立、自研的事件引擎与四人界面。单次伤害计算和四人自动战斗分别启动，各自保存配置。数据库里的面板、倍率、削韧和资源字段能进入模型，但它们不能代替完整的角色被动、敌人行为和场景脚本。没有实测锚点的规则不标为游戏对拍通过。

## 本次补充

- 自动战斗固定四个位置，四人分别选择角色并编辑光锥、遗器、面板与行动策略；不预设主 C / 生存位。替换保留位置 ID 与其他三人的配置。编辑与应用分开，未应用的配装草稿不改变当前战斗。
- 可配置双 C、多 C 或四人输出阵容；结果逐人统计伤害、输出占比、实际扣血、治疗、护盾生成与行动次数。
- 动作循环使用动作键，例如 `skill, basic, basic`，在正常回合循环。资源不足时本回合改用普攻，下一回合继续循环；终结技独立插入。
- 指定敌人阵亡后重选存活目标；同速顺序随站位改变。
- 伤害属性来自技能，抗性穿透和元素击破也按技能属性选择。
- 无效资源、目标、循环动作、持续效果和未指定成本的终结技在运行前拒绝。未应用的 JSON 草稿阻止运行。
- 最后一个敌人阵亡时停止追加队列，避免多个就绪终结技因无目标而反复排队。

## 覆盖范围

| 部分 | 状态 | 证据 / 限制 |
| --- | --- | --- |
| 行动值、速度变化、拉条与推条 | 已实现 | 数值回归；尚无实测录像对拍 |
| 战技点、能量、固定回能 | 已实现 | 明确输入的动作资源规则 |
| 普通动作、终结技、追加动作队列 | 已实现 | 动作完成后结算；不涵盖所有技能内部中断 |
| 逐段伤害、扩散、随机弹射 | 已实现 | 真实动画逐段权重仍缺失，不能用平均段数冒充 |
| 治疗、护盾、持续伤害、反击 | 基础规则已实现 | 自定义动作及明确持续回合规则 |
| 全角色被动、光锥、套装、星魂 | 未完成 | 导入携带缺口，严格模式拒绝 |
| 敌人动作、转阶段、召唤、跨波 | 未完成 | 不能由敌人的 HP / SPD 自动推出动作脚本 |
| 控制命中、冻结、纠缠、禁锢、超击破 | 未完成完整复刻 | 元素击破暂需配置规则；不自动猜测 |
| 真实游戏伤害与生存对照 | 待验证 | 实测锚点目前为空 |

配置和日志均可导出；日志包含输入快照。用相同快照和随机种子可重放。在“游戏实测对照”中录入动作 / 伤害的 AV、目标、出现序号和伤害值，可定位首次差异。

## GitHub 候选复核（2026-10-14）

进一步检查了以下原作者仓库，未复制其代码：

- [louis0617/hsr-mechanic-sim](https://github.com/louis0617/hsr-mechanic-sim)：提供以黄泉队为例的触发规则及两套模型对照；README 说明许可证仍待确认。模型互相吻合不等于实际游戏吻合。
- [realm-labs/starclock](https://github.com/realm-labs/starclock)：提供 Rust 战斗参考、行动轴与内容覆盖文档；README 区分已验证、观测和项目策略，不能把项目策略当成游戏保证。
- [LoranAndos/Honkai-Star-Rail-Combat-Simulator](https://github.com/LoranAndos/Honkai-Star-Rail-Combat-Simulator)：包含角色、光锥、忆灵与队伍计算模块；仓库主页未提供明确许可证或完整游戏对拍说明，暂不直接整合代码。

目前优先保留一套浏览器可离线运行的计算核心；后续按选定队伍和场景逐项补机制，并记录每项来源、测试条件和实测差异。
