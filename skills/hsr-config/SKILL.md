name: hsr-config
description: 将中文自然语言、崩铁黑话和简称转换为 HSR Analysis 网页可导入的四人队伍配装，生成导入链接并应用。用于“红花刻龙全01”“花火换风翁160速”等配置修改；处理角色形态、专武、星魂、遗器、面板与行动策略。

把用户描述变成项目实际校验过的配置，并导入本地四人战斗网页。默认项目 `D:\HSR Analysis\伤害计算器`；若不存在，查找当前工作区的 `package.json` 与 `_scripts/compile_team_config.mjs`，不要下载或执行其他项目。

1. 读 [配置约定与黑话](references/configuration.md)。执行 `python scripts/compile.py --project "D:\HSR Analysis\伤害计算器" --catalog` 查询当前数据库名称和 ID；不凭记忆编造 ID、倍率、敌人或技能效果。网页只做离线校验，不调用在线 AI。
2. 按用户原意组织 `hsr-analysis/team-v1` JSON。已有队伍用局部修改，只填写用户提及的队员和字段，未提及项保留网页当前值；告诉用户哪些配置沿用。新角色需要完整面板或合法的六件遗器。角色顺序不同于默认队伍时明确 `slot`。
3. 用户说的是游戏角色详情面板时用 `statsBasis: out-of-combat`；明确提供扣除光锥套装的引擎面板时用 `engine-input`。战斗中截图不能冒充局外面板。百分比写 `"65%"`，回能写总倍率 `1.1944` 或 `"119.44%"`。不猜缺失的主副词条，不把 `00` 当作没装备光锥。
4. 对会改变结果的歧义，先利用当前队伍和上下文消歧；仍不能确定时只问最少的必要问题。可先生成其余配置草稿，`unresolved` 非空的草稿不能导入。用户已说明的专武、版本、星魂等不反复询问。不为“完成配置”虚构配装或改变战斗模式。
5. 把 JSON 保存为项目 `outputs` 下的文件。执行 `python scripts/compile.py --project "..." --input "...json" --output "...hsr.json" --url "当前本地战斗页面地址"`。脚本调用项目同一校验器，失败就修正输入，不降低严格模式。预检基于参考队，最终网页按当前队伍重新验证。
6. 优先直接导入：打开脚本返回的本地 URL（配置放在 `#hsr-config=` 片段，不发送给服务器），读取预览后点击“应用导入配置”，确认页面显示“已导入”。用户要求配置即已授权这项可撤销的本地操作，无需额外确认。若当前浏览器支持读取 UI，复用当前战斗页；不要通过隐藏全局变量或开发控制台修改状态。浏览器工具不可用时交付可点击的导入链接和 JSON 文件，并说明尚未应用。
7. 页面不可用时检查已有本地服务器；需要时用项目 `node hsr_server.mjs <未占用端口>` 启动并保持窗口隐藏，以 `/battle` 为 URL。离线成品 `战斗模拟器.html` 同样支持链接片段与文件导入。不要为导入队伍发布、推送、上传到 GitHub 或改动关卡。

完成后只报告实际应用的角色和关键变更、沿用项及未解决项。未运行战斗就不声称已验证伤害；有 0T 目标也不能把训练敌人计算说成真实关卡复现。
